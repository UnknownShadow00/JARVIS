# Evidence can fail; legacy must remain unaffected

ENOSPC, quota/inode exhaustion, EACCES/permission failure, unavailable path/device, corrupt/partial input/storage, unsupported version, invalid clock and uncertain commit are shadow evidence failures. Return truthful nonaccepted receipt or expose unresolved caller failure; do not silently drop, claim persisted, repair meaning, retry automatically, invoke a model/tool, change mode/policy or fall back to audit/P2.

The affected measurement coverage is incomplete; durability failure need not imply bytes are absent. If storage itself prevents durable diagnostics, independently recoverable upstream accounting must prevent a later clean-window claim. The sink alone cannot provide that guarantee. No exception can be allowed into legacy because evidence failed; future evaluator/scheduler integration must isolate sink calls/errors/cancellation and preserve exact legacy reply/stream/permission/confirmation/dispatch/external state.

Timing/CPU/disk contention is a future D07 resource-isolation concern. This pure contract cannot prove runtime latency isolation; no synchronous request-path or background mechanism selected. Whether storage failure pauses new evaluation is D07, not a sink policy. Never free disk automatically to continue.
