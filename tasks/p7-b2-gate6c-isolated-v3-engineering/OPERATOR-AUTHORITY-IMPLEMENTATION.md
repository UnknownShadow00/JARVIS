# Authority seam, not an installed privileged control plane

The candidate accepts only three fixed canonical signed verbs: OPEN_HOLD, AUTHORIZE_ONE and TERMINAL_STOP. Body keys are exact, max8192bytes; noncanonical/duplicate/nonfinite JSON, unknown fields, command strings, wrong bindings, invalid nonce/signature/peer or missing user presence refuse. Approval expiry is at most60s and is checked again for permit consumption. The injected verifier returns the named operator identity plus user-presence evidence. Durable control rows retain identity, nonce, verb and signed-body digest; replay is refused. Neither API Bearer token nor continuation is an operator credential.

Runtime starts CLOSED_INITIAL or CLOSED_RECOVERY_HOLD. OPEN_HOLD verifies zero accepted state, exact READY checkpoint and clean ownership and sends no generation. AUTHORIZE_ONE binds the next fixed transport, Core-owned session and request commitment. Request acceptance spends it durably. Terminal association and a verified coordinated checkpoint precede next eligibility. Four successful attempts close complete; abort/stop/uncertainty closes permanently. Stop records no fabricated provider terminal. The ordinary HTTP/WS adapter has no opening endpoint; a WS continuation frame only selects an existing Core session. Voice and arbitrary protocol methods are unavailable.

This is a pure verifier interface tested with dummy HMAC keys and dummy root peer tuples. The real signer, approval ceremony, kernel SO_PEERCRED extraction, root-owned helper/socket, release verification and system unit are NOT implemented or installed. Passing a uid=0 tuple in a test is not OS authentication. Same-UID jarvis documentation/mode0600 never distinguishes Codex from the operator.

Future approved arrangement: non-login V3 service account; root-owned immutable release/import/config parents; a named human operator identity that Codex cannot impersonate; a narrow root-supervised local helper performing kernel peer/process verification and verifying explicit operator user-presence signatures. Bind approval to reviewed release/config hashes, exact executable/import tree, boot/start/PID/invocation, epoch, checkpoint, purpose/expiry/nonce. Root pins the one global lineage root. Public service can only receive fixed validated control records; no arbitrary commands or general sudo/polkit privileges. Record the actual operator action without storing credential bytes or conversation content.

Future credentials must be human-provisioned directly into the approved new private service boundary. Do not copy/read the old Bearer token with Codex. Source/config readable but not writable by service; controller/lease/audit roots writable only by service; root/operator archives immutable; Codex has only an export of reviewed secret-free evidence. Old V2 artifacts remain under their original owner and hashes. A specific importer may validate read-only archives or create versioned new files with explicit provenance after approved retirement; no permissive ACL or recursive ownership change.

Local code injection by a fully privileged administrator remains a trust assumption. Peer UID/PID alone cannot establish human intent. Root deployment, account creation, signer enrollment, credential provisioning and all actual permissions require separate authorization.
