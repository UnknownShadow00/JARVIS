# Disposable schema 5 ledger and manifest 3 checkpoints

The prototype accepts only an explicitly attested zero-use CLOSED_COMPLETE predecessor with input initialization complete, no unknown, a pinned archive and EXPLICIT_ZERO_USE_RETIREMENT. The child identity must differ. This is a test model of a future attestation, not a proof the current OPEN V2 epoch has retired. A privileged future archive validator must produce that attestation; raw caller booleans are not independent evidence.

A fixed deployment-root lineage-reservation.json is created O_EXCL/no-follow, written once and fsynced with its directory before child creation. Exactly one child namespace may use that root. Partial reservation/initialization remains evidence and refuses another successor. The approved global root must be fixed by protected release authority: creating arbitrary alternative roots is not something a user-owned database can prevent. No reset, migration, restore or pruning API exists.

SQLite uses FULL synchronous, DELETE journal, exact schema validation, integrity/foreign-key checks and one lifetime writer flock. Accepted IDs/ordinal/transport/session/permit/provenance cannot be updated/deleted by normal schema operations. A transaction spends a unique permit and creates the acceptance atomically, before provider work; crashes before commit leave no acceptance, after commit retain the high-water mark. One lineage has ancestor_count0 by the narrow retirement rule. Nonzero/incomplete/aborted/uncertain ancestors are refused, not hidden by a new counter. Four global ordinals and two-per-transport sequence are enforced. A broader resumed nonzero lineage is deliberately not implemented.

Opening records operator identity, exact signed-body digest and nonce. Permits bind session/transport/private request commitment and expire at acceptance. Source/config/release/epoch/boot/start/PID/invocation/challenge must match injected bindings. Restart constructs CLOSED_RECOVERY_HOLD after any prior control/acceptance; terminal states remain terminal. No automatic re-open, token replay or unfinished request reconciliation occurs.

Backups create a fresh UUID directory, copy SQLite under the writer lock, fsync component files, include minimized receipts and lineage reservation, and write the manifest last. Manifest3 binds content hashes, lineage, runtime identity, accepted count and event high-water mark. READY requires known substeps, clean leases, settled acceptance, exact receipt join and local legacy delivery. Partial append/orphan evidence permits only FORENSIC_INCOMPLETE; it cannot authorize another permit. Validation refuses corrupt members, mismatched counts/joins, substituted manifests and a newer supplied current high-water mark. It does not implement an actual restore. Receipt append/join and backup share the store lock.

Qualification includes transaction-boundary injected crashes, a real killed disposable SQLite writer in canonical backup tests, partial append, lineage reservation crash, corrupt schema/backup, exact checksums and newer-evidence refusal. No VM power cut, storage-controller cache loss or disk-hang experiment was run. Filesystem durability beyond SQLite/fsync contracts requires later real-filesystem qualification. Database/filesystem calls are synchronous in this prototype; a blocked fsync can stall the event loop and durable stop completion. The in-memory stop fence is set first, but a strict30s wall-clock guarantee under disk stalls is not proven. A reviewed supervisor/I/O-failure contract is required before deployment; do not invent a successful terminal record after timeout.
