## Credential path and authority

Only main after the Core UID/hostname/TTY checks and explicit human acknowledgement calls the fixed credential loader. All parent components are opened with directory descriptors and O_NOFOLLOW. Credential opens use O_RDONLY|O_NOFOLLOW|O_NONBLOCK. Type, UID/GID 1000, mode 0600, link count1, no xattrs, bounded size and stable read metadata are checked. The actual file was NEVER opened, parsed, hashed or copied by Codex. Nonsecret metadata identifies device 64512/inode 2922135 and its exact mtime/ctime; private directory inode 2892922 is likewise pinned.

The existing /home/jarvis/.config is mode0775, owner/group jarvis. Its group inventory currently has only jarvis as primary member and no explicit additional members. The security argument does not rely on that inventory: the loader pins the exact .config device/inode, opens its child without following symlinks, requires UID 1000/private 0700 and exact child device/inode/mtime/ctime, then requires the exact private credential identity. Another group member could deny access by renaming a directory, but cannot substitute an attacker-owned/symlink/different-inode child or file that passes these checks. All private child/file checks happen on opened descriptors. No production permissions or contents were changed. A legitimate replacement/rotation causes local refusal and requires fresh review; do not edit the pins to bypass it.

The parser accepts exactly one JARVIS_API_TOKEN assignment, unquoted or simply single/double quoted, 32–512 allowed ASCII Bearer characters, optional final LF, no embedded whitespace/control/escaping/comments/extra assignment. It never sources or executes env syntax. Compatibility with the real unseen file is intentionally left to human execution; malformed input causes local sanitized refusal before networking.

## Data exits and failure handling

The only secret-bearing exits are the required Authorization Bearer headers to two hardcoded AF_INET loopback connections at127.0.0.1:8000. No DNS resolution, environment proxy, redirect, retry or external destination exists. The utility never places the token in a URL/query, argv, environment export, stdout/stderr, file or hash. The sole hashlib call computes SHA1 of a random public WebSocket nonce plus the RFC GUID; it does not hash credential material. Header bytes are not logged or serialized to evidence.

Static outputs are an acknowledgement prompt and a fixed status line. Exception text/traceback is never formatted; malformed responses and auth exceptions are caught. An unexpected interruption after entering checks produces UNKNOWN rather than asserting no requests happened. Each socket has a five-second cumulative deadline and context-manager close. Successful WS validation sends exactly one masked normal-close 1000 frame and expects a close 1000 echo. Data/ping/abnormal close, negotiated extension/subprotocol, duplicate headers, oversized header, timeout and unexpected status fail closed without retries or further data frames. REST failure prevents WS entirely.

The initial input buffer is overwritten, file/socket descriptors close, and the main token reference is dropped when checks end. RLIMIT_CORE is set to0. Python's immutable bytes and kernel buffers cannot be reliably scrubbed; no stronger erasure guarantee is claimed. The private short-lived process and no-output/no-persistence design are the boundary. Same-UID/root debuggers, compromised Python/kernel, a privileged substitute server or a malicious operator are outside the guarantee. The procedure uses -I -S -B to ignore Python environment/user-site customization and avoid bytecode output.

TTY/hostname/acknowledgement checks reduce accidental execution; they are not cryptographic proof that a human launched it. Codex is explicitly prohibited from running the real loader. Offline tests import only guarded code; dummy-root loader qualification redirects every os.open into fixtures. Audit counts show 0 production credential access attempts and 0 external INET/DNS attempts. No credential value comparison or secret-value scan was performed.

The utility has no persistent one-use counter. At most one REST and one WS occur per invocation. The operator must not relaunch after success, failure or uncertain interruption. It cannot open admissions or prove Gate5 complete; separate state evidence is required.
