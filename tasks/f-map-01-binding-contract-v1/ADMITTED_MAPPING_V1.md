The exact current handler `_APP_MAP` key set is: `blender`, `calc`, `calculator`, `chrome`, `cmd`, `code`, `discord`, `explorer`, `firefox`, `notepad`, `obs`, `paint`, `powershell`, `spotify`, `task manager`, `taskmgr`, `terminal`, `vs code`, `vscode`. The V1 binder applies P3 canonicalization first and requires the resulting `app` string to be an exact member of that set. `vs code` / `visual studio code` specifically canonicalize to `vscode`; other case/spacing rewrites are not copied from handler behavior. Unknown names fail before an executable projection, even though the handler itself also returns an error for unknown names.

The URL row requires P3 `OPEN_URL` with full resolved route target, exact lowercase `http://` or `https://` scheme, an absolute nonempty host, no whitespace/control characters and no username/password component. This conservative predicate is required by P4 row 12's “absolute URL only; no credentials in URL” and P3's exact URL route; URL bytes otherwise remain unchanged. No model URL repair, scheme insertion or search fallback. The future validator must implement this predicate without network/DNS calls. Unknown extra keys are forbidden for both rows even though handlers may ignore them; proposal comparison uses the entire map.

`permission_projection.target` preserves `route.target` exactly; `canonical_target` equals P3's canonical target argument (`app` or `url`). Raw and canonical maps are identical to the corresponding `CanonicalizationResult` fields. `approval_mode` comes from JARVIS safety config; both rows have no required constraints, so `satisfied_constraints=frozenset()` and `overwrite=None`. P7 still calls `permissions.decide()` at S07. A valid binding is never an ALLOW token or confirmation.
