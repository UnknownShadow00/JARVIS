# Recorded replay is not fresh live evidence

Authentic recorded replay means previously captured/sealed provider-derived canonical adapter data with demonstrated original turn/request association and origin. Preserve the known original correlation/AdapterRequest, capture/normalizer origin reference and parser contract/implementation version where available; explicitly label it replay. Current reparse uses the canonical parser and must name its version; a historical parser version is not silently replaced.

An existing seal proves file integrity, not provider generation. A synthetic JSON recording or hand-created typed output remains synthetic even after sealing, recording, replaying or parsing it. Current N-R1 contract corpus/N-R2 tests and the R8 frozen 116 + 53 unseen cases were passive fixtures without live model calls; their pass scores do not become authentic live or provider-origin replay evidence.

If original association/origin/version is unknown, identify that gap. It may still support clearly labeled offline fixture/contract validation, but cannot claim replay-origin authenticity or be counted as fresh live input. Remapping a recorded turn in a test harness remains an explicit test/replay action, never a new provider response for that turn. Preserve historical documents/labels; make the new measurement classification truthful.

Adapter-data replay is independent from AdmissionMode.RESULT_REPLAY, which admits recorded trusted execution results/invocations and is out of INITIAL_TURN inert shadow. Never choose that mode merely because adapter input is a replay recording. No replay success confers execution authority.
