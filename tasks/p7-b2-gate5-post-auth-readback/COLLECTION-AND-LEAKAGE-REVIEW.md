# Read-only collection and evidence review

The new post-state.py and continuity.py are copies of previously sealed/reviewed Gate5 read-only collectors with their output root changed to this new evidence directory. They never call controller initialization, admission opening, database migration, ownership acquisition/release/reset, backup creation/restore, service lifecycle operations or network model APIs. SQLite connections use mode=ro plus query_only and read transactions. Ownership snapshot and validate_bundle are the reviewed non-mutating interfaces. Python bytecode writes are disabled.

minimized-readback.py adds bounded audit suffix metadata, fixed journal marker/timestamp correlation, helper source hashes without imports/execution, prior file metadata comparisons, relevant user-unit names/states, startup ownership component binding and inventory comparisons. Audit/client payloads and raw journal messages/HTTP headers are never serialized. Timestamps originate in server records; operator execution UTC remains unspecified. A normal WS disconnect is kept distinct from pilot attempts.

Collection audit hooks block credential-file opens and network operations and restrict Python writes to new evidence. Subprocess commands are fixed read-only Git/systemd/journal/process/socket metadata inspections; no environment dumps, show-environment, secret-bearing shell history or token command arguments are used. Credential metadata/ACL names only were read. This is a reviewed collection boundary, not a general sandbox against a hostile privileged host.

The offline runner isolates source/tests, guards all credential/production-runtime opens, blocks INET/DNS and external writes, and uses dummy credentials/fake transports/AF_UNIX peers. Its manifest/log/guard artifacts show no violations. Expected fixture children and socket peers ended with the tests.

No real secret was available for a value-comparison scan; production credential contents or token hashes were never accessed. Evidence leakage review therefore uses source/collection review, fixed sanitized status fields and structural checks for serialized sensitive headers/content. No raw provider/conversation content, real Authorization header, request-header dump, authentication exception or credential assignment is in task results. Helper hashes are source hashes, not token hashes. Documentation/source mentions of credential APIs and header names are not captured values.

All prior seals are reverified without modifying prior evidence. Current live controller metadata matches prior Gate5 even though a SQLite backup's physical bytes differ from its live database; logical associations, exact schema/integrity and unchanged live-file metadata establish continuity. No repair or rewrite is performed to obtain a pass.
