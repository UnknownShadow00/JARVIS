# Local-only prerequisite gate

No host inspection was performed. R2 supplies no getent, id, sudo, PAM, NSS enumeration, network lookup or VM permission probe. The gate executes only against already approved bounded nonsecret file bytes. It does not authorize any query after passing.

Before future R19, an existing console custodian must establish that the approved paths are local mounts, not autofs/network/FUSE routes, and that the interpreter, loader and libraries are trusted. The original read-only R01 remains first. Do not discover locality by opening an unreviewed mount. Without this prior nonsecret custody evidence, STOP before inspection.

First inspect metadata/hash for `/etc/nsswitch.conf`, then bounded content. `local_gate.nss_gate` requires explicit, unique `passwd`, `group`, `initgroups`, `sudoers`, `hosts`, and `netgroup` entries equal to `files`. Missing entries/defaults, compat, systemd, sss, ldap, nis, winbind, dns, bracket actions, duplicate entries, continuation/ambiguous syntax or encoding fail. This intentionally conservative subset can reject a normal host configuration. Do not edit that host configuration to make it pass.

Inspect approved public `/etc/passwd` and `/etc/group` bytes only after file-custody review. Require one existing nobody/65534, primary GID65534, no alternate UID alias, noninteractive shell and no supplementary privileged groups. Credential-bearing passwd formats block; never read shadow/gshadow or private credentials. Passwd data alone does not demonstrate absence of management rights.

Bounded metadata and nonsecret policy review must cover sudo.conf plugins, sudoers and every include, NSS modules, PAM/include/helpers and remote logging, polkit/D-Bus rules and sockets, Proxmox ACL/group mappings, executable/set-ID/file capabilities, credential-storage ancestry and ACLs, backup/storage/config/service/socket access, and readable files that could expose VM authority. No `sudo -l`, authentication attempt, private-content read, VM tool or API may be used. Custom sudo.conf directives fail the automated gate. Policy semantics require an independently signed complete inventory, including implicit/default rules and local mount custody. The gate validates that review's hash and required assertions; it does not infer permission denial from words in a policy file.

The required review includes `all_includes_local`, `no_remote_policy`, `no_network_pam`, `no_custom_helpers`, `vm_authority_denied`, `credentials_denied`, `local_mounts_no_autofs`, `complete_inventory`, an exact file-to-hash map and independent-review digest. Every field must be present and true. Unknown sources, opaque rules, remote/group plugins, incomplete credential inventory, activity by nobody, or inability to prove denial => BLOCKED_NO_LOCAL_UID_PROOF. Do not create an account, alter policy, disconnect networking or request credentials.

Use R10's bounded `/proc/*/status` scan immediately before installation and every creation. It reads numeric UIDs/GIDs/groups only; it never reads environ. Require complete output, no errors and no nobody processes, except processes positively bound to the already owned case during observation. Numeric `User=65534`, `Group=65534`, empty SupplementaryGroups, guard UID/eUID/GID/eGID and runtime groups must all agree. Empty SupplementaryGroups does not neutralize implicit NSS membership; hence this gate precedes service creation.
