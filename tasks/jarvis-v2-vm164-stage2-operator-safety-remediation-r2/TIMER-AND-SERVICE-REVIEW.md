# Systemd interface review and unresolved qualification

Core argv retains paired transient units, Type=exec, fixed numeric non-root User/Group, absolute OnBootSec represented by `--on-boot`, WakeSystem=yes, AccuracySec=1us, RandomizedDelaySec=0, RemainAfterElapse=yes and Persistent=no. RuntimeMaxSec is3s for timeout and10s otherwise; TimeoutStartSec5s, TimeoutStopSec2s, KillModecontrol-group, SendSIGKILLyes, no restart. Resource ceilings: MemoryMax128M, TasksMax16, CPUQuota10%, NOFILE64, CORE0. Null stdin and journal outputs are explicit. The catalogue preserves all sandbox/environment/credential/command-reset assignments; no defaults are silently assumed.

Type=exec concerns actual service execution, not proof that a timer's future payload ran. Nonzero missing-executable creation may precede203/EXEC. Missing dependency can produce inactive rather than failed timer state. Neither is promoted to observed success. SupplementaryGroups reset does not remove groups obtained via NSS; local-only membership denial must precede activation.

New R2 details requiring independent scrutiny include `--expand-environment=no`, empty command/credential assignments, SetLoginEnvironment=no, EnvironmentFile reset and the double-quoted ExecCondition command token. Inline payloads and guard code are encoded as space-free hex-decoding Python tokens to permit exact argv comparison without shell parsing. There is no shell, percent or dollar interpolation in those tokens. The guard is executed under the same non-root service restrictions. Its public binding includes the window and generation; the pinned canary file is unchanged.

Available evidence: the audit's retained LOCAL-PRIMARY-DOCUMENTATION.json and sealed R3 systemd_codec interfaces. These document transient service/timer pairing, normalized microsecond properties, environment sources, non-root identity and ExecCondition concepts for their installed interfaces. They do not establish exact systemd257.13 command parser acceptance, show representation or journal continuity. No network documentation lookup or host command was performed for R2.

The proposed readback contract requires complete raw properties, including ExecCondition, ExecStart, credential/environment resets and compound TimersMonotonic. Unknown formatting, duration tokens, absent properties or differences in normalized names are BLOCKED. The current strict parser is a proposed acceptance contract, not a claim that all fields are exported exactly this way on pve. Obtain installed matching documentation during separately approved read-only preflight, then capture harmless waiting/service readbacks in qualification. Do not alter sealed R3 or rewrite raw output to fit a parser. If a syntax cannot safely be established before creation, stop with a blocker and prepare a new offline revision.

For D in BOOTTIME microseconds and observed offset interval [B1−M,B2−M], test raw NextElapseUSecMonotonic N against both N=D and N+offset containing D. Accept only an unambiguous, documented-consistent domain, or exact-version documentation resolving otherwise equal-clock ambiguity. UNKNOWN, offset drift>1000us, changed boot or UTC/boot elapsed discrepancy>1s fails. Two waiting captures are required for ordinary cases. WakeSystem=yes selects wake-aware scheduling but is not proof that the machine can physically wake. No suspend/reboot/reexec test or VM operation is in scope.
