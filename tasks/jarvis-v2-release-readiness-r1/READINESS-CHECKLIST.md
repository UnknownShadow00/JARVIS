# Exact release readiness criteria

The packet distinguishes an offline controlled-test candidate from live readiness.
An item is not passed by a historical suite, a synthetic signature or an approval
record alone. RESULTS.json and release/BUILD.json supply exact final identities.

| Offline controlled-test criterion | Required evidence |
|---|---|
| Frozen source | Same current 102 app Python hashes in every selected final mode; actual dirty-baseline patch and full source archive |
| Broad repository inventory | Every collectable repository case identified; collection errors zero; all safely selected cases pass; exact hardware/desktop exclusions listed |
| Obsolete tests resolved | Retired JSON-writer/public-completion/tool-confirmation expectations replaced with durable shared-authority/no-effect contracts; originals retained in before/ and failing run evidence |
| Whole application lifecycle | Actual ASGI lifespan + API auth + queue + scheduler + signed synthetic IPC + receipts + shutdown/restart; no fake package/module substitutes |
| Authorization | Missing/blank/wrong bearer denied by main and embedded authority router, including /ready; independent synthetic transport permit, scope, UUID, signatures, expiry and replay controls verified |
| Legacy execution inert | Tool registry/callables/getters/chat/vision/confirmation/dictation/resource mutation cannot dispatch real effects or fabricate completion |
| Conservative recovery | Original UUID/payload retained; report is not completion; separate offline record/publication permits; UNKNOWN never causes redispatch; restored approval remains inert |
| Witness/checkpoint/ledger protection | Prior witness/generation/ancestry verified; missing/rolled-back/corrupt custody fails; signed history/receipts independently rechecked |
| Filesystem hypothesis | Original same-UID SQLite swap harness rerun and rejected; unsafe ancestors refused before creation; component symlink races and retained-ancestor replacement rejected; limitations explicit |
| Crashes and resource bounds | Independent subprocess SIGKILL stages, stale owners, partial commits, injected disk-full and restart tests; unchanged namespace/CPU/RSS/disk/FD/process limits |
| WebSocket reliability | Binary/oversize/audit/cancellation cleanup; pending accept + active cap; all sends/closes bounded; failed live peer retains count until handler exit |
| Defaults and context | Dry-run true; default/example automatic host controls false; no token or authority provisioned; boot/dictation/tracing off; Docker context excludes state/credentials |
| Dependency identity | Verified retained 28-package target plus three hash/RECORD-checked supplemental wheels; exact 31-package offline lock and metadata; no fresh advisory or full desktop graph claim |
| Independent security review | No open critical/high/medium reviewed delta findings; exact nine final source/default/context pins; tests attributed separately |
| Candidate publication | Deterministic sorted archive, fixed metadata, byte-identical rebuild, no-replace publication, no symlinks/unsafe names/runtime config/secrets/state; reader verifies every member |
| Evidence integrity | Every initial predecessor file unchanged, symlink inventory and source/input manifests verified, canonical log prefix preserved and completion appended to project log |

The shared development checkout is not an immutable release. While concurrent
writers operate there, the source archive and detached candidate worktree are the
release authority. Do not launch or claim qualification of a mixed shared checkout.
Promotion/deployment requires explicit identity comparison and a separate decision.

## Live-stage blockers — all must be resolved independently

- A separately approved finite identity-only broker window with actual installed
  source/CA/release, target, UID/GID, grant and time bindings.
- Protected independent token/signing/checkpoint/witness custody and actual
  restricted principals; current administrative group membership must not bypass it.
- Qualified existing broker/worker installation, preissuance/canary evidence, exact
  VM164 identity, no-NIC/exclusive serial/no-root-console and effective token scope.
- Current installed transport/API/TLS/seccomp/device/egress enforcement evidence.
- Physical filesystem power-loss/WAL/locking/rename/fsync/quota qualification;
  SIGKILL and injected ENOSPC are insufficient hardware durability evidence.
- Credentialed authority/readiness clients and one-worker/frame-limited ingress;
  shared bearer is not multi-principal authorization or a browser credential design.
- Review of mutable Docker/action references, full intended dependency/model graph,
  current advisory status and installed/native artifact identity before deployment.
- Any real JARVIS adapter needs a later authorization/custody design and review;
  the current socketpair endpoint shares the trusted process and cannot be promoted
  into a hostile-principal or live broker boundary by changing configuration.

The one consolidated proposal is LIVE-READONLY-PROPOSAL.md. None of these conditions
is established through production access by this sprint, and none is waived.
