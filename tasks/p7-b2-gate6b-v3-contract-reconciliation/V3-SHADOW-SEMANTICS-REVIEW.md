## Why exact equivalence is not yet established

The legacy path is not a pure response formatter. The reviewed YAML selects main `qwen3-nothink`, router `gemma3:4b`, and `http://localhost:11434`. `app/config.py` also supports JARVIS_OLLAMA_BASE_URL. No process/environment/credential content was inspected, so the YAML endpoint is **not a claim about the running process's effective legacy endpoint**. Granite is independently pinned to .200 and the qualified alias. The D06 scope records loopback as a legacy endpoint; that is not a lease for another legacy model.

`IntentRouter._classify` uses rules then a real router generation, with error-to-respond fallback. `ComplexityRouter.decide` chooses legacy model/80,150,700-token behavior. LLMClient has up to four network tries, 600-second HTTP timeout, optional streaming, error speech, and no qualified Granite request/lease contract. `build_prompt` incorporates procedural-memory context and a legacy prompt containing action-tag instructions. These cannot be inherited into an opened pilot by merely calling `_process` with a tool registry stub. Dry-run=false is configured, and dry-run policy alone is not a tool-free boundary.

Fresh execution of the exact pure direct-responder source proves that **none of the original four proposed prompts is a deterministic direct reply**, including word-form arithmetic. Numeric arithmetic is supported, but replacing all prompts with that subset changes the sampling plan and needs operator approval. Canned replies, fake production legacy output, a model swap to Granite, and silently changing the main/router endpoint are rejected.

Gate1 explains one-provider enforcement through the shadow driver's intake/active/provider-task checks. That proves one qualified shadow generation at a time; it does not prove serialization with the ordinary legacy client. Four accepted shadow attempts must never be reported as four total provider calls if legacy/router generations also occur.

## Recommended decision: L, bounded legacy compatibility

Retain a separate capability-limited legacy response adapter and observational Granite driver. Capture the same pre-turn history, durably consume the permit/acceptance before **any** router or responder generation, serialize all explicitly approved provider substeps, deliver only legacy output, then settle shadow evidence and checkpoint before another permit. Reuse reviewed pure prompt/response logic only through audited interfaces. Do not call unrestricted `_process`, `_process_stream`, intent fallback, resource manager, registry, confirmation, comms, TTS or error-speech handlers. A non-conversational classification or proposal/action tag stops the attempt without execution. Uncertain legacy disposition also blocks Granite and every later permit.

This can preserve **legacy-visible/Granite-observational roles**, not promise byte-identical stochastic replies or unchanged timing. It requires explicit approval of: actual legacy endpoint/model identities; whether one bounded router call remains or approved deterministic classification replaces it; legacy prompt/memory snapshot; per-substep token/context/deadline/native limits; no-retry/nonstreaming legacy transport; resource-qualified ownership and endpoint-wide mutual exclusion; sanitized legacy delivery evidence; serialized scheduling and changed error behavior. Granite's frozen profile is not extended to other models by analogy. Until this decision and qualification, the adapter is unavailable and the design cannot open.

Alternative D: operator-approved inputs that demonstrably remain within the exact deterministic legacy reply subset, with audited deterministic intent classification and no legacy model traffic. This retains legacy reply provenance for those inputs but changes the chosen experiment. Granite-only output is an explicitly different experiment and is not the recommended reconciliation.

**Required operator semantics decision:** approve a bounded legacy compatibility contract (recommended), or expressly approve a revised deterministic input experiment. Current evidence does not support “exact original experiment preserved under all frozen constraints.” Infrastructure/ledger design work can proceed to review independently; no production implementation is authorized here.

## Evidence per accepted attempt

D09 records global attempt ID/ordinal/transport/session, LIVE/eligible=false, consumed permit and accepted set before work. Named legacy substeps need distinct before-send/possible-send/terminal/delivery metadata; they must not masquerade as Granite collector/D04 receipts. Granite retains native request/response association, before-transmission/known-transmitted/known-terminal facts, canonical normalization/parser/passive evaluation, exact D04 submission/receipt join and D06 disposition. A successful settled shadow attempt has one exact Granite D04 receipt; failures may have zero/uncertain receipts without refund. D09 `submissions` counts observation submissions, not every provider transmission. Raw legacy/Granite content, authorization headers and credentials stay out of task evidence. Only actually delivered legacy text feeds in-memory bounded continuation history; Granite text is discarded after passive processing.
