# Deterministic derivation rules available now

1. Transport authenticates/normalizes a request into original text and a JARVIS-controlled session; P1 mints/loads correlation IDs. Transport control fields are discarded before control-plane projection. No request flag can select a privileged route, tool, policy class or result.
2. P2 supplies a same-session immutable snapshot and classifier key projection. P3 `classifier.classify(request, classifier_context)` then `router.route(request, classification, router_context)` produce the only request class, route, action and target. P7 performs these calls again using the same fields; input snapshots/version must remain stable. No separate classifier/verb/lane rule is copied.
3. The available-action set must derive from an approved JARVIS capability inventory intersected with P4 registration. `DEFAULT_ROUTER_CONTEXT` or model-advertised schemas alone never prove live availability. **Inventory source unresolved.**
4. For an actionable, resolved route with a frozen action/capability pair, a separately approved **closed** binder must produce exactly one tool namespace and complete raw argument map, including target correspondence. No such binder table exists today; do not choose nearest names, synthesize missing arguments, drop unknown fields or borrow legacy/harness extraction.
5. Call the existing P3 canonicalizer once for that JARVIS-bound tool/raw map. Carry its exact version, canonical map and applied rules. Construct `PermissionRequest` from routed action/target, declared capability, matching raw/canonical maps and P4-owned configuration/constraint evidence. P7 revalidates them at S06 and P4 decides at S07.
6. JARVIS builds `AdapterRequest` using the same approved tool namespace in its advertised schema. Advertisement is a consistency check, not the source of authority. Proposal parsing occurs after the deterministic projection is fixed; model output cannot change the expected side.

Rules 1–2 and 5–6 are existing composition constraints, not a newly executable mapping. Rule 4 and the live source in rule 3 must be resolved before F-MAP-01 can be marked closed. Given identical frozen request state, approved inventory, policy and schema versions, the projection must be identical; no random/clock/provider/global mutable selection. JARVIS-assigned timestamps and stored observations are separate settled turn inputs, not mapping entropy.
