# Proposed correction and disk protection sequence

Status: reviewable design and pure synthetic predicates only. No installer integration, new ISO, write-protection implementation or deployment authorization. [guard_proposal.py](tools/guard_proposal.py) has no CLI, collector, subprocess, device access, marker, or write operation. It cannot install Ubuntu. Existing sealed r4 files are unchanged.

## Identity and topology

1. Require root, exact DMI UUID, loopback-only interfaces, exact target hardware serial, bytes and model. Inventory **all** block nodes; never filter to the preferred path before counting candidates. Correlate nested `lsblk` rows with independent `/sys/class/block` membership, major:minor, kernel device kind and parent links. Missing inventory, unreadable metadata, duplicate paths/major:minor, inconsistent classification or unsupported graph all refuse.
2. Classify physical whole disks using kernel topology plus `lsblk TYPE=disk`; in this VM context that includes virtual whole disks. `udev DEVTYPE=disk` alone is insufficient because optical/loop devices can also have it. Count every whole-disk candidate, including read-only and nonmatching disks. Require exactly one and require it to be the expected path. Device mapper, LVM, mdraid, multipath, crypt, zram, unexplained slaves/holders or other storage layers refuse rather than disappearing from the candidate list.
3. A partition is excluded from **identity-owner counting only** when `TYPE=part`, udev `DEVTYPE=partition`, a positive sysfs partition number and the nested/PKNAME/sysfs parent all agree on a known whole disk. Prefixes such as `sda1` or a shared serial are not parent proof. Unknown/orphan/stacked/mislabeled nodes refuse. This avoids both mistaking inherited identifiers for a second disk and hiding a real disk under a partition label.
4. Require the whole target to match all three exact observed udev values, independently of its hardware serial. Count their owners across whole disks. As an additional conservative check, retain r4's refusal if an optical or loop node claims any expected target identifier. Only proven partitions are excluded. A second disk with distinct identifiers still fails the single-disk requirement; one sharing any or all identifiers also fails, even if `/dev/sda` would win a path match.
5. Identity analysis can explain valid partition inheritance. **Installation admission still rejects every target partition or dependent**, plus any recognized signature, nonempty filesystem/partition-table type, target mount, swap use, holder, slave, or incomplete report. A missing/failed/timed-out signature command must never be converted to an empty report. No `preserve`, override, recovery, retry-on-initialized-disk or ignore-signatures mode is introduced.
6. Other media must be read-only optical or verified read-only loop devices. Loop backing must resolve entirely to authenticated installer media or RAM, never to the target or a file backed by it. Real collection must resolve loop backing paths, mount source chains and namespaces; the prototype's `backing_origin` is a synthetic contract value, **not a supplied string that production should trust**.

The prototype likewise expects sysfs `kind` to be derived independently: partition attribute, loop directory/backing data, SCSI optical type and device topology. It is not a second copy of the `lsblk` value. Its `dev` maps to `lsblk MAJ:MIN`. `mounts`/`swaps` represent observed block major:minor references, not path-string matching. A real collector must also inspect mount namespaces, swapfiles and open descriptors/mappings; it must fail when inspection is incomplete. None of those production collection assurances is claimed by synthetic dictionaries.

The original exact storage matcher remains a conjunction of path, udev ID_SERIAL and ID_PATH, with no wildcard/fallback. A future new disk needs a **new approved** hardware serial and observed udev binding; the current constants cannot be copied blindly onto another target. UUID, credentials, cloud disablement, isolation, mount policy, offline artifacts and later qualification requirements remain mandatory.

## Protect before probing, partitioning or formatting

An early-command patch is insufficient. The required state machine is:

| State | Disk access and allowed transition | Failure behavior |
|---|---|---|
| PROTECTED_BOOT | New approved disk has an independently enforced write barrier before initramfs/cloud-init/udev/installer activity. All storage-capable services start inhibited. | Barrier absent/unproven: NO-GO before target exposure |
| INSPECT | Read-only identity, topology, signature and use checks; verify effective config/media/runtime and full writer inventory. Retain baseline externally. | Leave write barrier closed; no formatter launch |
| ARMED | One trusted supervisor owns a fresh boot/invocation-bound admission, exact config and target identity. No other writer can acquire access. | Restart, changed config, hotplug or loss of ownership invalidates admission |
| PREWRITE | With every worker still inhibited, take a second fresh inventory; prove same disk, topology, config and bytes. Release the barrier only to the single supervised writer. Validate fixed/writable state immediately before its first storage command. | Any change refuses; no automatic retry or reused success |
| INSTALL | Invoke only reviewed storage actions and supervise their complete lifetime, including transient systemd units. Record first write and subsequent stage results. | Block further dispatch; retain mutated disk and logs; no cleanup/wipe/rollback |
| REVIEW | Postinstall/late checks plus boot/readiness review under later approval. | Partial state stays untrusted; qualification remains separately gated |

Implementation requirements:

- Prefer a hypervisor/backend-enforced read-only attachment for initial inspection **if the exact backend supports it and it is independently verified**. Otherwise a reviewed initramfs barrier must engage before any potential writer, not inside Subiquity after cloud-init. Do not assume a particular Proxmox `readonly` option works for this scsi backend; no live change or example mutation command is authorized here.
- A guest `blockdev --setro` alone is late if run in early-commands and can be cleared by privileged software. Read-only mount flags, `flock`, `udevadm settle`, a success file, a process-name scan, or one empty `wipefs` result are insufficient protection.
- The supervisor must enforce exclusive storage access for the whole run. All other userspace trees must lack target write/discard/unsafe-ioctl access and the privilege to lift the barrier or escape confinement. Consider reviewed kernel/cgroup/device and capability confinement, plus host-side backend exclusivity. Existing writable descriptors must not survive admission. If this cannot be established for the live environment, stop; do not replace enforcement with “no process seen”. Arbitrary unconfined root cannot be made safe by a Python predicate.
- Read-only reconnaissance has its own strict expectation that the barrier is engaged. It does **not** produce install admission. The existing writable-target rule applies at the final prewrite boundary after the supervisor's controlled handoff, while every other worker remains inhibited. The prototype models that final writable predicate only; its `ro=False` requirement is not compatible with claiming a protected read-only reconnaissance pass.
- Bind admission to exact VM UUID, boot ID, physical/backend volume identity, hardware serial, udev identities, major:minor and sysfs path, capacity, media/config/guard/snap digests, supervisor invocation and empty-disk baseline. Copy/freeze measurements; do not retain a mutable fixture reference. Recheck independent views after udev settles and immediately before opening the write path. A hotplug/replacement/config change invalidates the whole decision even if `/dev/sda` remains the name.
- A persistent `/run/subiquity/early-commands` stamp must never authorize writes. Revalidate on **every** server/worker invocation, including restarts. On a failed/partial installation, do not restart into a successful cached admission. Inhibit automatic restart paths; failure handling must not issue storage or lifecycle cleanup commands.
- Put a mandatory fail-closed check in the actual Subiquity storage-dispatch boundary before `run_curtin_step`, including before `meta_clear`, disk wiping, block-meta, formatting, restore-image or any equivalent writer. Cover every possible storage dispatch branch, not only the ordinary direct layout. Repeated read-only post-partition checks cannot demand a virgin disk; instead use phase-specific exact planned topology bound to the same supervised transaction, and stop on any failure. Never reopen a failed transaction by declaring its changed disk acceptable.
- Do not rely on curtin's default `early` stage: 7403 explicitly selects the partitioning stage. A dispatch check is defense in depth behind the preboot barrier and exclusive supervisor, not a substitute for them.
- Journal UTC and monotonic time, boot ID, PID/cgroup/unit InvocationID, measurement hashes, command argv and exit status for each boundary. Preserve evidence outside the target; do not store admission evidence on the disk about to be formatted.

## Validation required before another ISO or VM attempt

This investigation documents supported mechanisms but does not attribute the actual mutation. Hold media construction until the operator evidence timeline resolves the first failing automatic invocation versus any prior writer, or an explicit reviewed investigation disposition accepts the remaining uncertainty and the containment design addresses it. No new ISO is created by this packet.

After separate implementation/build authorization, exercise the actual pinned Subiquity/curtin and protection mechanism in a wholly disposable, separately approved environment with file-backed disks and a known baseline. Observe backend writes from **before boot**, not merely from formatter startup. Required scenarios: first automatic early failure, valid single disk, inherited partition identifiers with initialized-disk refusal, two disks including read-only/nonmatching/cloned identifiers, signatures without visible partitions, wrong UUID, holders/mounts/swap, stale stamp, service restart, competing/orphaned curtin, config override, hotplug/identity drift, and attempted writes through another service. Every negative case must show no target-byte change and no storage dispatch. The positive case must show that its first write follows admission. Verify failure after admitted writes preserves the partial disk and prevents automatic retry.

Read-only metadata inspection and pure AST tests cannot establish this kernel/backend guarantee. Production collector, supervisor, full runtime rehearsal and operator approval remain open work. No Gate 6K qualification is part of that installation rehearsal.
